# 回环与变更控制（Backtracking & Change Control）

> 配套「运行协议：确认门 + 回退」的**运行时机制**。确认门管"向前走"，本节管"往回改"——什么情况触发回边、回到哪一层、改完怎么续跑、怎么不破红线。
> 一句话：**每次回环 = 一次变更请求（CR），一条回边，一份决策日志，出口三关校验。**

---

## 一、三类触发源（谁发起回边）

| 触发源 | 场景 | 动作 |
|---|---|---|
| 用户主动 | 「回到 S07 改一下」「S06 项目载体换掉」 | 直接走回边 |
| 评审打回（人在环闸门） | 某步「④ 等验收确认」时用户不确认并指出问题 | 评审点=闸门，不通过即触发回边 |
| 自检失败 | `check_s20_integrity.py` 非全绿（红线被破） | 回到对应步骤修复 |

> 课程开发的"反复"**大多来自人工评审打回**（"单元审完觉得不行，打回重做"），不是 AI 自纠。所以**人在环闸门是回边的主触发器**：每阶段收口（④ 等验收确认）就是评审点，评审不通过 → 触发回边；通过 → 才进入下一步。

---

## 二、显式回边清单（7 条典型回边）

| 回边 | 触发情形（例） | 回到 | 层粒度影响面 |
|---|---|---|---|
| S08 教案 → S07 单元 | 做教案发现单元设置 / 课时 / 任务要改 | S07 单元设计 | 单元层 → 备课层 |
| S07 单元 → S06 整体 | 单元设计牵动整体目标 / 周次 / 作品链 | S06 整体设计 | 整体层 → 单元层 → 备课层 |
| S08 教案 → S06 整体 | 教案发现总目标 / 周次要调 | S06 整体设计 | 整体层 → 单元层 → 备课层 |
| S06 整体 → S04 课标 | 设计偏离了课程标准的模块 / 能力目标 | S04 课程标准 | 课标层 → 整体层 → 单元层 → 备课层（全链路） |
| S09 备课 → S02 资源 | 备课发现资源缺口（素材 / 案例 / 工具缺失） | S02（`ti-s02-resource-collector` 补采） | 资源层 → 备课层 |
| S04 课标 → S03 图谱 | 课标能力点调整，反哺能力图谱 / 岗位画像 | S03 能力图谱 | 图谱层 → 课标层 → 整体层 → 单元层 → 备课层 |
| S05 学情 → S07 单元难度 | 学情分析显示起点能力与假设不符 | S07（难度曲线） | 单元层 → 备课层 |

> 未列出的回边按同一逻辑推导：**回边终点 = 变更真正落地的层**，不是变更被发现的层。例如教案里发现"总目标要调"→ 目标在课标层（S04），故回 S04，而非 S06。

---

## 三、影响面判定矩阵（层粒度，决定级联重算范围）

回边触发后，**不是无脑重跑全部**，而是按"改动落在哪一层"判定必须重算与可不动：

| 改动落在 | 必须级联重算 | 可不动（除非改动直接触碰） |
|---|---|---|
| 图谱层（S03） | S04 → S06 → S07 → S08 | S01 / S02 视改动性质 |
| 课标层（S04） | S06 → S07 → S08（全链路） | S01 / S02 / S03 视改动性质 |
| 整体层（S06） | S07 → S08 | S04 课标（除非改模块 / 能力目标） |
| 单元层（S07） | S08 | S04 / S06 骨架 |
| 备课层（S08） | 同级子步互检（按级联影响表） | 上游均不动 |

> 本表与「运行协议」的**级联影响表（步骤粒度）**互补：本表是"层"粒度决策规则，级联影响表是逐行状态标记依据。执行时：先用本表判影响面（回复用户一句话点明），再按级联影响表把具体步骤标记为 `⚠ 需重做`。

---

## 四、决策日志（回环不失控的前提）

- **文件**：`<课程根>/99_工程与脚本/课程开发决策日志.md`（append-only，**永不覆盖、永不删除历史**；由 `create_workspace.py` 骨架预留）。
- 每次回环 MUST 追加一条，格式：

```markdown
## [YYYY-MM-DD] CR-N：<一句话概括>
- 触发点：<步骤 + 具体位置，如 S08 教案 第3周 06_PPT>
- 触发源：<用户主动 / 评审打回 / 自检失败>
- 改了什么：<如 单元任务X 课时 2→3>
- 为什么改：<如 教案里实训时长不够>
- 影响面：<层粒度，如 单元层 → 备课层>
- 处理：<回到 S07 重做 → 级联 S08 → S20 校验>
- 结果：✅ 完成（时间戳）/ ⏳ 进行中
```

- **目的**：可追溯"改了几次、每次为什么"，评审与验收时直接可查；也是 S20 收尾校验的旁证材料。

---

## 五、回环出口三关（改完必须依次通过，缺一不可）

回边执行完、向下游续跑前 MUST：

1. **不变量校验**：`scripts/check_s20_integrity.py` 全绿（PGSD 编号连续 / 命名纪律 / 课标·整体设计两层分离 / 无特定证书体系字样）——**回改最易破红线，出口必查**。
2. **审批门**：重做的步骤走完整四拍（① 报计划 → ② 等开工确认 → ③ 报成果 → ④ 等验收确认）。
3. **决策日志**：把该 CR 的「结果」更新为 ✅。

然后从回边终点继续向下游推进（下游已在影响面矩阵中标记 `⚠ 需重做`，逐个走审批门重做）。

---

## 六、禁止清单

- **禁止**回环后跳过审批门直接续跑下游。
- **禁止**回环后不更新进度状态表 / 决策日志。
- **禁止**无边界回环：单次 CR **只回一条边**；多个问题合并为一次 CR 统一评估，不连环触发。
- **禁止**覆盖旧版：原地修改或 `_v2.md` 另存，**防丢失优先于目录整洁**（与「回退机制」一致）。
