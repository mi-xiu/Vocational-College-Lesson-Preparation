# 职教课程建设 · 备课全流程工作流（修订版 18 步）

把一门职教课程"从空盘到可上课的备课包"拆成**三阶段、7 个专家角色**的协作工作流（备课包展开后共 18 步）。这是顶层编排工作流（专家团「课程总监」），负责定顺序、守纪律、控分项、做 S20 收尾校验；具体的文档生成交给 **7 个专家角色对应的步进技能**与工具。

> 注：上方「三阶段 7 专家」是**专家团路由维度**的划分；下方「18 步主清单」按建设工序细分为四建设子阶段（S01–S09，其中 S08 展开 10 子步），是**另一维度的工序划分**，二者不冲突，最终统一经 S20 收尾校验。S02 并入②、S08 并入⑤、S05 并入④ 已在路由表与对应技能中落地。

## 何时使用

- 用户要做职教精品课、智慧课程、课程标准、教材、单元设计，或说"备课""课程包""第一次课程包"。
- 用户提到 S01、S02、S04、S07、S08、备课九步法、18 步、能力图谱、学生画像、典型工作、整体设计、备课包、单元设计。
- 用户想"从零开始"建设一门课，或已有方向但缺系统交付物。
- 用户希望产出物结构化、可评审、可上传网盘。

## 三条不可破的纪律（先讲，全程守）

1. **顺序铁律**：先调研 → 再标准 → 后落地。典型工作任务分析（S02）必须在课程标准（S04）**之前**当输入；学生画像（S05）必须移到教学开发段、整体设计（S06）**之前**；案例台账并入 S02 不再单列；14 周进程属于整体设计（S06），**不进课标**。
2. **三层文件纪律**：`课程标准(S04)` 在前（学习领域层，只到模块、不绑项目/周次）→ `整体设计(S06)` 居中（学习情境框架层，绑定项目/作品/周次）→ `单元设计(S07)` 在后（学习情境层，落到周任务）。三者是"抽象能力 → 具体载体"的派生关系，单元设计的每个任务必须能回溯到课标能力点。
3. **目标纵向一致性**：目标从典型工作任务（S02）一路贯穿到备课包考题（S08），是同一职业源头在不同抽象层的展开，不是凭空新造。链路：典型工作任务 → 课标能力点(S04) → 整体设计项目(S06) → 单元周任务(S07) → 备课包考题(S08)。下层必须能回溯上层（用"模块×作品调用矩阵"落实）。

> 这三条纪律与 BAG 工作过程系统化（学习领域→学习情境）、OBE / 反向设计（UbD）完全一致。`references/step-theory-mapping.md` 逐条解释了每步对应的教育理论名词与依据。

## 课时确认铁律（S05 强制门，优先级等同运行协议）

> **一句话**：进入 S06 整体设计之前，S05 MUST 用 AskUserQuestion 向客户确认「每周课时数 × 总周数」，即使人才培养方案已载明也须客户二次确认；未确认不得进入 S06。

- 这是**全团铁律**，覆盖任何课程（无论培养方案是否提供周学时 / 总周次）。
- 周学时 × 总周次 MUST 等于总学时；若客户确认值与培养方案不一致，以**客户确认值**为准，并在 S05 报告课时核对节标注差异与原因。
- 编排层在 S05 → S06 路由处 MUST 检查：S05 报告「课时安排核对」节是否含「客户已确认」标记；无标记则拦截 S06 开工。
- 目的：培养方案常只给总学时（如 16 学时 / 第二学期），不写每周 × 周数分布；直接套用会导致 S06 周次进程建立在未确认假设上，后续整体设计 / 单元设计全链返工。人必须在环确认，机器不得代过。

## 五条红线（总师统一兜底，全专家 MUST 遵守，S20 契约双保险）

专家团任一角色产出的文档，MUST 通过以下五条红线校验；编排层在 S20 收尾统一复核（脚本 `check_s20_integrity.py` 固化其中多条）：

1. **PGSD 编号统一**：能力点全程沿用全局 PGSD 四维（P方法/G通用/S技能/D发展）与既有编号；下游（S04/S06/S07/S09）不得另起一套维度或编号。
2. **课标·整体设计两层分离**：`课程标准` 在前（能力母本，只到模块、不绑项目/周次）→ `整体设计` 居中（绑定项目/作品/周次）；两文件并列、不混写、文件名不互相代指。
3. **命名纪律**：课标 `<课程名>-课程标准.md`；整体设计 `<课程名>-课程整体设计（<项目版>）.md`；周包 `备课包_第N周_作品X_主题`；L0–L3 模板文件带 `{学校}{专业}_{L编码}_` 前缀（见 `Ti_课程模板库整理`）。
4. **禁 特定证书体系**：证书对接统一称"证书 / 职业技能等级证书 / 行业认证 / 企业认证"；全文档禁止出现"特定证书体系 证书 / 特定证书体系 技能点 / 特定证书体系 过程证据"等表述。
5. **量规二值 + 标★**：评价类判定统一用 `✔/✘` 二值判据 + `★`（关键项）+ 对应闸门，不套通用 4 级量表；未达 ★ 闸门视为不通过。

## 运行协议：确认门 + 回退（第 0 纪律，优先级高于本文件其余全部内容）

> 本节是本技能的**运行时宪法**。与下文任何步骤描述冲突时，以本节为准。
> 一句话：**这是 18 个「停—报—等—确认」的循环，不是一条跑到底的流水线。**

### 一、强制审批门（MUST）

**门粒度 = 18 道**：S01–S07 各 1 道，**S08 内部 10 个子步各 1 道**（S08 容器本身不单独设门），S09 1 道。

每一步 MUST 走完整四拍，缺一不可：

| 拍 | 动作 | 内容要求 |
|---|---|---|
| ① 报计划 | 执行**前**展示「本步计划」 | 本步目标 / 输入（来自哪一步的哪个文件）/ 方法与将调用的下层技能 / 预计产出文件的完整路径 |
| ② 等开工确认 | 停下等用户 | 用户明确回复「确认 / 继续 / 开始 / 可以」等肯定表述后，才可执行 |
| ③ 报成果 | 执行**后**展示「成果摘要」 | 3–8 条关键结论 + 产出文件完整路径 + 与上一步的衔接说明 + 更新后的进度状态表 |
| ④ 等验收确认 | 停下等用户 | 用户明确确认后，本步状态才置为「已确认」，才可进入下一步的 ① |

**禁止清单（硬红线）**

- **禁止**未获 ② 就开始执行本步。
- **禁止**未获 ④ 就进入下一步的 ①（**含 S08 内部相邻子步之间**）。
- **禁止**在一次回复内完成两个及以上步骤。
- **禁止**「我先把 S02–S04 一起做了，您最后统一看」这类批量推进话术。
- **禁止**把自己的「我将要做 X」当作确认——确认只能来自用户。
- **沉默 ≠ 确认**。用户没回复就停在原地等待，不得自行推进。
- 唯一例外：用户主动明确授权跨步连做（如「S05 到 S07 你一次做完不用问我」）。此时 MUST 先复述授权范围，且授权范围结束时立即回到正常门控。

### 二、回退机制（可跳回任意已完成步骤）

用户可随时说「回到 S03 改一下」「S06 的项目载体换掉」。技能 MUST：

1. **允许跳回任意已完成步骤**，不要求顺序倒退，不质疑用户决定，不要求「先做完当前步」。
2. **原地修改，绝不删除原文件**。同路径覆盖更新；改动较大时用 `原文件名_v2.md` / `原文件名_修订YYYYMMDD.md` 另存并保留旧版。**防丢失优先于目录整洁。**
3. **级联标记**：把被改步骤**之后所有**已完成步骤状态改为 `⚠ 需重做`，写入进度状态表，并在回复中一句话点明影响面：
   > ⚠ 你修改了 S03 能力图谱，下游 S04 / S06 / S07 / S08-1~3 已标记为「⚠ 需重做」。要现在逐个复核，还是先只改 S04？
4. **「需重做」≠ 自动重做**。标记后仍须走审批门：由用户确认重做哪几步，再从最早那一步重新进入 ① 报计划。
5. **回退后不得跳过门控**，重做的步骤同样走完整四拍。

### 回环与变更控制（CR 驱动，配套回退）

> 回退机制管「往回跳」，本节管「为什么回、回到哪、改完怎么续」。**每次回环 = 一次变更请求（CR），一条回边，一份决策日志，出口三关校验。** 完整规则见 `references/backtracking-change-control.md`（回边清单 / 影响面矩阵 / 决策日志格式 / 出口校验），执行前必读。

1. **触发源**：用户主动（「回到 S07 改一下」）/ **评审打回**（④ 等验收确认时用户不通过——课程开发的反复大多来自人工评审，人在环闸门是回边主触发器）/ 自检失败（`check_s20_integrity.py` 非全绿）。
2. **显式回边**：7 条典型回边（教案→单元 / 单元→整体 / 教案→整体 / 整体→课标 / 备课→资源补采 / 课标→能力图谱 / 学情→单元难度）。回边终点 = **变更真正落地的层**，不是变更被发现的层。
3. **影响面判定**：按「层粒度矩阵」（图谱 / 课标 / 整体 / 单元 / 备课）判级联重算范围，再按上面「级联影响表」逐行标记 `⚠ 需重做`。
4. **决策日志**：每次回环 MUST 追加一条到 `<课程根>/99_工程与脚本/课程开发决策日志.md`（append-only）：触发点 / 触发源 / 改了什么 / 为什么改 / 影响面 / 处理 / 结果。
5. **回环出口三关**（缺一不可）：① `check_s20_integrity.py` 全绿（回改最易破红线，出口必查）→ ② 重做步骤走完整审批门四拍 → ③ 决策日志落 ✅，然后才向下游续跑。
6. **禁止**：无 CR 的回环、无日志无校验的回环、单次 CR 回多条边、回环后跳过审批门。

### 四、展示规范（成果摘要怎么写）

每次「③ 报成果」MUST 含三块，**不要贴整篇正文**：

1. **成果摘要**：3–8 条要点，说结论——这一步定了什么、得出什么判断、和上一步怎么接。
2. **关键文件**：完整路径逐行列出，标注「新建 / 修改」。
3. **下一步预告 + 一句提问**，例如：
   > 下一步 S04 课程标准将以本步 P/G/S/D 能力点为输入。确认无误请回复「确认」；需要调整请直接说改哪里，也可以说「回到 S02」。

摘要正文不超过 20 行；用户要看细节会自己打开文件。

## 四阶段 · 18 步主清单（每步=一项相对独立、老师可独立完成并验收的工作）

> 设计哲学：**顺序听理论的、粒度听老师的**。一个步骤 = 一件能判断"做完没做完"的相对独立工作（WBS 工作包思想）。不把备课整体当一步（无从下手），也不无限拆细（变操作清单）。

### 阶段一 · 职业分析与任务提炼

**S01 职业 / 工作过程分析**
- 目标：产出区域产业与岗位就业证据，为课标定位、学生画像、典型任务提供输入。
- 理论：DACUM 职业分析 · 工作过程（Arbeitsprozess）· 职业科学。
- 对应技能/动作：WebSearch 搜产业/岗位/证书；show_widget 画薪资/趋势图。
- 纪律：偏"职业/工作过程"而不仅是市场；证书对接保留，统一称"职业技能等级证书 / 行业认证 / 企业认证"。

**S02 典型工作任务分析（含案例 / 资源调研）⭐**
- 目标：提炼岗位真实工作任务（典型工作任务 / Typische Arbeitsaufgaben），并同步完成案例与素材搜集（这里就是"案例台账"——用户做案例资源时本质在做典型任务分析的调研阶段）。
- 理论：BAG 典型工作任务 · 实践专家研讨会（EXWOWO）。
- 对应技能/动作：ti-s02-resource-collector 辅助搜集；用 WebSearch/本地资料建案例台账。
- 纪律：此步在 S04 课标**之前**；典型任务是课标的"原材料"，不是课标的一部分。

**S03 能力图谱（PGSD 四维）**
- 目标：把岗位能力拆成可观测、可考核的能力点，形成 P/G/S/D 四维图谱。
- 理论：PGSD 四维能力 · 行动能力（Handlungskompetenz）· 核心素养。
- 对应技能/动作：参照 `references/pgsd-model.md` 拆 S1…Sn / D1…Dn，写分级标准（初级=合格/中级=良好/高级=优秀）。

### 阶段二 · 课程设计

**S04 课程标准 ⭐在前**
- 目标：产出课程标准（能力标准母本）。课程定位、就业面向、PGSD 四维能力目标、模块骨架 M1…Mn、评价框架、岗课赛证口径、能力分级标准。
- 理论：学习领域（Lernfeld）· OBE 成果导向 · 泰勒原理 · 反向设计（UbD）。
- 对应技能/动作：`ti-s04-course-standard`。
- 纪律：只到模块层，不绑项目/作品/周次；含"课程评价标准"（反向设计的阶段1成果）。

### 阶段三 · 教学开发

**S05 学生画像 / 学情分析**
- 目标：独立产出学习者画像，作为教学策略与项目难度依据。
- 理论：学习者特征分析（Learner Analysis）· 最近发展区（ZPD）· 差异化教学。
- 纪律：在整体设计（S06）**之前**；是教学开发端输入，不是课标输入。

**S06 整体设计（含 14 周进程）⭐居中**
- 目标：把课标能力落进真实项目/作品，定项目载体、作品链、模块×作品调用矩阵、周次进程、学时分配、运营机制。
- 理论：学习情境框架（Lernsituation）· 行动导向（Handlungsorientierung）· 项目化教学（PBL）。
- 对应技能/动作：`ti-s06-course-blueprint`。
- 纪律：绑定具体项目/作品/周次；14 周进程在此，不进课标。

**S07 单元设计（含评价量规）⭐在后**
- 目标：以整体设计的"项目/任务/周次"为骨架，做单周单元教案 + 评价量规。
- 理论：学习情境（Lernsituation）· BOPPPS · 梅里尔首要教学原理。
- 对应技能/动作：`ti-s07-unit-design`。
- 纪律：从整体设计取"项目/任务/作品/周次/学时"，从课标取"素养维度/能力目标/评价结构/岗课赛证口径"（仅能力参考，不单独成教学单元）；单元粒度 1 单元=1 周=4 课时(180min)。

**S08 备课包（容器 → 展开 10 子步）**
按**反向设计（UbD）**重排：先定"拿什么证明学会了"（评估证据），再定"怎么教"（教学活动）。

```text
【评估证据 · 先定】
  S08-1 任务工单 / 工作页 / 实训指导书   ⭐职教核心（学生侧"练"的载体，BAG 工作页）
  S08-2 考题 / 任务命题                  （布鲁姆评价分类）
  S08-3 评价量规 / 评分表 / 互评表        （可直接发学生的打分依据）
【教学活动 · 后设】
  S08-4 教材 / 学材                       （外部选用或既定，先界定清楚）
  S08-5 讲稿                              （教师说，路径而非目标）
  S08-6 PPT                              （多媒体学习认知理论 CRT）
  S08-7 动画 / 重难点可视化              （双重编码）
  S08-8 微课                              （微学习 / 翻转课堂）
【保障与差异化】
  S08-9 设备 / 耗材 / 安全清单            ⭐职教核心（理实一体开课硬前提）
  S08-10 拓展 / 分层资源                  （呼应 S05 差异化教学）
```
- 理论对应技能/动作：教学材料开发（S08-4/5）、布鲁姆评价（S08-2）、BOPPPS/梅里尔（单元层）、多媒体认知/双重编码（PPT/动画）、微课理论（S08-8）。
- 纪律：S08-1~3（证据）先于 S08-4~8（教学）；动画可含于微课素材，边界在"成片 vs 独立可视化"。

### 阶段四 · 实施改进

**S09 教学实施与评价改进（闭环）**
- 目标：把备课包拿到课堂用，收集评价数据，修订课程。
- 理论：ADDIE 的 I+E（实施+评价）· PDCA · 反思性实践。


脚本行为：
- 建 `00_参考资料 … 08_申报与成果 + 99_工程与脚本` 全套目录 + 各 S0x 子目录 + 轻量占位 md；

## 网盘上传流程

每个文件生成后，按以下流程上传（脚本保留原重试逻辑）：

1. 用 `DeferExecuteTool` 调用 `mcp__netdrive__tdrive.file_upload` 获取临时上传地址、`confirm_key`、`task_id`。
2. 运行上传脚本：
   ```bash
   python3 ~/.workbuddy/skills/ti-s01-s09-course-build/scripts/put_with_retry.py \
     <signed_url> <file_path>
   ```
   该脚本会自动处理 `InvalidAccessKeyId` 等凭据失效，重试 3 次。
3. 如果 PUT 连续失败，重新调用 `file_upload` 获取新凭据，再试。
4. 用 `DeferExecuteTool` 调用 `mcp__netdrive__tdrive.file_upload_complete` 落库。

## 注意事项

- 数据口径透明，不要把招聘样本量当行业总量。

- 若用户没指定 `<项目载体>`，S06 必须提出 2–3 个候选真实项目并让用户选一个。
