# 方法论底座：两层原理、理论依据与术语纪律

本文件是 `ti-s06-course-blueprint` 的学理支撑。整体设计不是"把知识点排进周次"，而是把课标里的**能力标准**翻译成**可实施的项目化教学方案**。

---

## 一、PGSD → 模块 → 课标 → 项目任务 → 整体设计（两层推理链）

```
岗位典型工作任务
      │  (BAG / DACUM / 工作过程分析)
      ▼
PGSD 四维能力（P 职业素养 / G 通用能力 / S 专业技能 / D 发展能力）
      │  (结构化 → 编号 S1…Sn / P1…Pn / G1…Gn / D1…Dn)
      ▼
课程标准（模块 M1…Mn = 学习领域，只到"能力/模块层"）
      │  ── 回答"培养什么能力"── 课标是能力标准母本，不绑项目/周次
      ▼
典型工作任务分析（思路/方法/理论依据 + 技能点分解，K 系列支撑文档）
      │
      ▼
教学项目载体 + 阶梯式项目（P1/P2/P3）+ 具体 TW 操作清单 + 周次进程
      │  ── 回答"怎么教"── 整体设计是项目化落地方案，绑定项目/作品/周次
      ▼
课程整体设计文件
      │
      ▼
单元设计（90 分钟，骨架取自整体设计的 项目/任务/周次）
```

**关键纪律**：课标层只定义"能力与模块"，绝不写具体项目与周次；整体设计层才落地"项目 / 作品 / 周次 / 课时"。两层是不同交付物，不可混写。

## 二、典型工作任务分析的七种方法

| 方法 | 用途 | 在课程中的落点 |
|---|---|---|
| **BAG 实践专家研讨会** | 实践专家（企业骨干）从真实职业提炼典型工作任务 | 确定一级典型工作任务（如"完成一条短视频从创意到上线的全流程"） |
| **工作过程六步法** | 资讯→计划→决策→实施→检查→评价，结构化每个任务 | 早期可用作任务分析框架，最终产出改为"操作清单"口吻 |
| **DACUM 岗位任务图表** | 岗位 → 职责 → 任务 → 步骤，拆到可操作 | 行业调研 → 6 工作领域 × N 任务清单 |
| **典型情境锚定** | 用真实项目情境（如官方号运营）锚定学习性任务 | 项目载体选择（某真实项目账号等） |
| **PGSD 能力结构化** | 把任务要求逆推到 P/G/S/D 四维能力点 | 模块 ↔ 能力点 ↔ TW 矩阵 |
| **学习性转化** | 真实工作 → 教学任务（降难度、加支架、分层 A/B/C） | 教师支架式入门（老师给案例/策划，学生执行） |
| **技能点分解法** | 每个能力点拆初级/中级/高级可观测实施要素 | 单元设计 / 任务单 / 考核的单一数据源 |

## 三、理论依据（评审追问"凭什么这么教"时引用）

1. **工作过程系统化课程论（姜大源 / 赵志群）**：课程应围绕"完整工作过程"组织，而非学科知识体系。典型工作任务 = 工作过程的结构完整单元。
2. **行动导向教学（Handlungsorientierung）**：学生通过"行动"（计划—实施—检查—评价）建构能力，而非被动接受。
3. **情境学习理论（Lave & Wenger， legitimate peripheral participation）**：学习是"合法的边缘性参与"，真实实践共同体（如官方号运营团队）中成长。
4. **建构主义**：知识在学习者主动建构中生成，项目载体提供建构情境。
5. **CBE 能力本位教育**：以可观测、可测量的能力表现为目标，技能点分解即 CBE 的操作化。
6. **迁移理论**：阶梯式项目（初级→中级→高级）促进近迁移到远迁移。
7. **UbD 逆向设计（Wiggins & McTighe）**：先定预期结果（课标能力）与评价，再设计活动（项目任务），避免"活动导向"误区。

## 四、术语纪律（全项目统一，违反即返工）

- **证书口径**：禁用"特定证书体系"。统一用 `证书 / 职业技能等级证书 / 行业认证 / 企业认证`（如互联网营销师、全媒体运营师）。
- **分级口径**：`初级 / 中级 / 高级`（对应原合格/良好/优秀）。**整门课程合格 = 中级**。初级只是入门过渡，高级是冲刺优秀。
- **文件名**：课标 `课程标准-<课程名>.md`；整体设计 `课程整体设计-<课程名>（<项目版>）.md`。不得把课标写成"课程标准（整体设计）"，不得用"整体设计"代指课标。
- **PGSD 编号**：S1…Sn 等一旦定稿全项目统一，下游不得另编。
- **单元骨架**：来自整体设计的"项目/任务/周次"，课标模块 M1…Mn 只作能力参考，不单独成教学单元。
- **数据口径**：每个行业数据标来源机构 + 时间，不把样本量当总量。

## 五、阶梯式项目的难度递进逻辑

难度递进 = **技能点"初级 → 中级 → 高级"的进阶**，不是主观加难。

- 入门项目（P1）：教师支架式，学生照案例/策划执行走通流程 → 达成**初级**。
- 主线项目（P2）：长期真实运营，复杂度逐作品升 → 稳定达成**中级**（= 课程及格线）。
- 冲刺项目（P3）：高质量提升（爆款 / 参赛质量参考）→ 冲击**高级**。

评价只看是否达成对应档的"可观测实施要素"，不靠印象分。
