# ti-office-docs · 模板导出工作流（Ti08 模板导出专家）

## 定位（改名说明）
> 原「Office 文档专家 / 卫文档」→ 现「**模板导出专家**」。
> 职责转变：**不再自行发明 L0–L3 格式骨架**，而是以**用户/默认模板为唯一格式真源**，把项目
> 已产出的 md 母本内容精准"套"进模板——**格式零改动，只替换内容**。

## 默认模板库（已固化 · 三件套）
目录 `templates/`：
- `课程标准-模板.docx` + `课程标准-模板-spec.json`
- `授课计划-模板.docx` + `授课计划-模板-spec.json`
- `单元教案-模板.docx` + `单元教案-模板-spec.json`

> 这三份即"**默认输出模板**"。任何课程（如《AI短剧编剧》）均套用其格式；用户也可上传/指定
> 自定义模板替换或补充其中某份。

## 标准工作流（5 步，含"先问后做"与"模板规范化门"）

**第 0 步 · 模板规范化门（接受模板前必做）**
- 拿到模板（默认三件套 或 用户上传）→ 跑 `scripts/school-template/optimize_template.py <模板.docx>`
  抽 `*-spec.json`（段落 match 键 + 表结构 mode + 列宽 + 表头 + 合计行）+ `*-data.example.json`。
- 审查 spec：合并单元格是否清晰、占位符/旧文本是否清扫、样式字体是否一致、表头是否完整、
  章节骨架是否与本项目母本可对得上。
- 若发现**不清楚 / 不规范**处 → 列出问题清单，**请用户自行修改**，或**与用户一起修改模板**，
  直到达到"能完全复刻"的程度 → 再接受该模板进入生成。
- 未经规范化门通过的模板，不得进入第 3 步生成。

**第 1 步 · 询问用户有哪些模板可提供（首问，必做）**
- 生成前先问用户：本次要产出哪几类文档？用**默认三件套**，还是用户**自定义模板**
  （上传路径 / 指定文件）？确认范围与模板来源。
- 若用户只给部分模板（如只要单元教案），则只导出对应文档，其余告知用户未在本次范围。

**第 2 步 · 从项目抽取内容（按映射表）**
- 内容专家已出 md 母本（课程标准 / 整体设计 / 单元设计 等）。本专家按
  `references/模板字段映射.md`（模板字段 ↔ 项目来源 ↔ 是否已具备 ↔ 需补充）抽取、重组内容。
- 注意：**本项目母本结构与模板八章式骨架不完全对齐**（如《AI短剧编剧》课标为十节式），
  须按映射表做"重映射/重组"，而非直接复制粘贴。

**第 3 步 · 保真套格式（render）**
- 用 `scripts/school-template/` 管线：`optimize` 已产 spec + 各文档 `*-<课程>-data.json`
  + `course.yaml`（身份/共享骨架单一真源）→ `render_template.py` 渲染。
- 输出 docx 的字体/字号/合并/列宽/页眉页脚 **严格等于模板**，仅替换文本与表数据。

**第 4 步 · 审核核对（verify · 必做）**
- 逐份跑 `verify_faith.py <模板.docx> <成品.docx> --spec <spec.json>`：
  - 结构级：列数 / 表头行 / 合计行 / 数据行签名 ⊆ 模板 / 段落[样式+字体] 一致。
  - 内容级：关键字段存在、含「配分/比例」列合计 = 100、占位符 `{{ }}/{% }` 无残留、旧文本已清除。
- **全绿才算通过**；任何红项必须回到第 3 步修正后重跑，不得带病交付。
- 核对基准 = 当前所用模板（默认三件套 或 用户本次提供的模板）。

**第 5 步 · 交付 + 归档**
- 成品放各步骤 `word版/` 或对应目录；md 母本永不删除。
- 记录本次所用模板文件名与版本，便于回环复现。

## 红线（沿用全团六条 + 模板纪律）
1. 无特定证书体系；证书通用口径（职业技能等级证书/行业认证/企业认证）。
2. 量规二值 ✔/✘ + ★ 闸门；**例外**：学校模板自身用百分制 / □10□8 量表时，以模板格式为准，交付前提示用户。
3. **格式零改动**：除替换文本/表数据，不得改模板字体/字号/合并/列宽/页眉页脚。
4. 模板未通过"规范化门"不得进入生成。
5. md 母本永不删除；成品可编辑（原生形状非图片）。

## 学校官方模板保真管线（引擎，已固化）
> 纪律：**先 optimize 再 render**。任何类似学校模板，禁止每门课现场重写 Python 探查模板；
> 一律先跑优化器产出 spec（一次性、永久复用），再做渲染执行。

| 阶段 | 脚本 | 输入 → 输出 |
|---|---|---|
| 优化（一次性） | `scripts/school-template/optimize_template.py <模板.docx>` | 模板 → `*-spec.json` + `*-data.example.json` |
| 渲染 | `scripts/school-template/render_template.py` | spec + `*-<课程>-data.json` + `course.yaml` → 保真 docx |
| 校验 | `scripts/school-template/verify_faith.py` | 模板 vs 成品：结构级 + 内容级（关键字段/配分合计=100） |
| 编排 | `scripts/school-template/build_course.py <课程名>` | `course.yaml` 单一真源 → 一键三件套 + 逐份校验 |

参考规格卡见 `templates/*-spec.json`（已对本次三件套跑通）。校正规则库 `references/SPEC_RULES.md`、
专家团衔接契约 `references/EXPERT_INTEGRATION.md`、完整图文流程见 `references/school-template-pipeline.md`。

## 单元教案通道（通用导出 · 课程无关 · v1.3.0 新增）

> 把"单元教案导出逻辑"从单课程项目脚本提升为**技能级通用通道**，与任何课程解耦。
> 完整说明见 `references/unit-lesson-plan-channel.md`。

| 文件 | 角色 |
|---|---|
| `scripts/unit-lesson-plan/engine.py` | 通用段落引擎（pPr+rPr 双继承 / 删块 / 清扫 / 定位） |
| `scripts/unit-lesson-plan/unit_channel.py` | 通用运行器 `export_unit / export_units` |
| `scripts/unit-lesson-plan/单元教案-fieldmap.json` | 默认单元教案模板的段落映射（模板级，课程无关） |

**三正交分离**：模板怎么排（fieldmap，技能内）· 教什么（unit 数据，课程级）· 旧模板换皮（sweep，课程级）。
新增课程 = 复用 fieldmap + 提供 unit 数据 + 提供 sweep，无需重写导出脚本。

**S07 → Ux 路由触发**：当 S07 单元设计（Ti06）产出 `单元设计.md`（U1–U8）且用户要求"输出可上课的单元教案 docx /
按默认单元教案模板导出"时，主理人或用户把每个单元派发给 Ti08 → 加载本通道，把 Ux 单元设计内容映射为 unit 字典 →
`export_unit(...)` 生成 `XX-单元教案-Ux.docx`（格式零改动）→ `verify_faith.py` 逐份保真校验全绿交付。
单元教案通道只做格式套用，**不重写教学逻辑**，教学科学性以 S07 母本为准。

**关键纪律与坑（已固化）**：
- **单一真源**：身份/共享骨架只写在 `course.yaml`，改一处三文档同步；长表单篇散文按文档独立维护在 `*-data.json`。
- **vMerge 合并单元格**：模板表格含纵向合并时 `cell.text=` 多行会错位 → 重建表按 `merge_cols` 直写。
- **fill 模式合计行**：模板末行是合计行，填完删多余行；勿误判 rebuild。
- **段落匹配**：用全文精确匹配最稳；模板段落带尾随空格时用 `rstrip()` 回退。
- **新插入段落必须同时继承 pPr + rPr**：内容重写（如教学过程替换）时，用 `make_para()` 新建段落只复制 run 的 `rPr`（字体）会丢失段落 `pPr`（首行缩进 `ind firstLineChars`、行距 `spacing line`），导致新段回退为无缩进/默认行距。**必须在脚本开头用 `get_ppr()` 抓模板正文段 pPr 一并复制**（本项目模板：`firstLineChars=200` 首行缩进2字符 + `line=360/auto` 1.5倍行距）。
- **宁绿不红**：校验一次跑通即绿灯，替代人工抽表。

## 技术要点
- python-docx：中文字体必须设 `a:ea`（`rPr` 追加 `a:ea typeface`）。
- 表格：python-docx 用 `Table Grid`；md 表格 → docx 表格。
- 批量：脚本须单文件自包含（沙箱可能拦截本地模块 import）。
