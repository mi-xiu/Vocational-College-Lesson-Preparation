# EXPERT_INTEGRATION.md — 专家团衔接契约（office-docs ↔ 内容专家）

本文件定义**内容专家**与 **Office 文档专家（gzv-office-docs）** 之间的产出/消费契约。
目的是让上游专家（course-standard / course-blueprint / unit-design 等）的 md 产出
能**直接**被 `_spec/md_to_course.py` 转为 `course.yaml` 骨架，再由 `build_course.py` 渲染三件套。

## 1. 分层职责（不可越界）

| 层 | 专家 | 产出 | 是否进 course.yaml |
|---|---|---|---|
| 内容权威 | course-standard / competency-map / course-blueprint / unit-design | **md 真源**（模块/周次/单元/评价） | 是（骨架部分） |
| 编排 | 课程总监(lead) ti-s01-s09-course-build | 路由 + 状态 + 变更回溯 | — |
| 渲染/格式 | **gzv-office-docs（本专家）** | docx/pptx/xlsx | 消费 md，不编内容 |

> 红线：office-docs **不**在自身硬编教学法内容（杠杆 B 自动生成骨架必须由内容专家完成）。
> office-docs 只做"容器 + 适配器 + 渲染"。

## 2. 内容专家应产出的 md 契约格式

文件名建议 `<课程名>-课程骨架.md`，结构如下（`|` 分隔字段，`## ` 分节）：

```
# 课程名：纪录片创作
- 课程代码：03089
- 课程类型：专业核心课
- 学时：64
- 学分：4
- 开课学期：第三学期
- 适用专业：传播与策划
- 授课对象：传播与策划专业二年级学生
- 任课教师：滔滔
- 学院：文化传播学院
- 教研室：传播与策划专业教研室 制
- 学校：明德职业技术学院
- 学年：2026—2027学年第一学期
- 编制日期：二〇二六年九月一日

## 模块（→课标表0 + 授课计划项目载体）
1. 纪录片认知与类型辨析 | 6
2. 选题策划与田野调研 | 10

## 内容要求（→课标表1：知识|技能|思政）
纪录片认知与类型辨析 | 纪录片定义、流派… | 能调研… | 树立正确价值导向…

## 考核组成（→课标表2：项目|配分）
过程性考核成绩（50%） | 考勤、职业素养（规范） | 20%

## 周次进程（→授课计划表1：周次|授课顺序|内容提要|总学时|理论|实践|重点难点|作业）
1 | 1 | 项目一：纪录片认知与类型辨析\n内容提要：… | 4 | 2 | 2 | 重点：… | 课后：…

## 评价样表（→课标表3：序号|评价内容|评价要点|配分|评价标准|评价计分，配分合计=100）
1 | 知识掌握情况 | 纪录片策划… | 20 | 熟悉… | □10□8 □6 □4 □2 □0
```

## 3. 流转命令

```bash
# 内容专家产出 md → 转为 course.yaml 骨架（合并写入）
python _spec/md_to_course.py <课程名>-课程骨架.md --merge

# office-docs 一键渲染三件套（身份+骨架已单一真源）
python _spec/build_course.py <课程名>
```

## 4. 给内容专家技能的建议（需回灌）

- `ti-s03-competency-map` / `ti-s04-course-standard`：在产出课标 md 时，附加一节
  `## 模块` + `## 内容要求` + `## 考核组成` + `## 评价样表`，采用上面契约格式。
- `ti-s06-course-blueprint` / `ti-s08-teaching-plan`：附加 `## 周次进程`。
- `ti-s07-unit-design`：单元散文仍独立产出，但其"模块/周次归属"须与 course.yaml 一致。

这样三件套"源生一致"，口径漂移风险归零，且 office-docs 无需重复录入。
