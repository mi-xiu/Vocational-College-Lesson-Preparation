# SPEC_RULES.md — 学校模板规格卡校正规则库（E）

本文件固化"模板 → 规格卡 → 渲染"过程中的踩坑与校正启发式。
新模板接入 `optimize_template.py` 后，按本规则人工 refine 生成的 spec，
避免重复排雷。规则按"症状 → 判据 → 修正动作"组织。

## 1. 表格模式判定（mode）

| 模板表特征 | 选 mode | 理由 |
|---|---|---|
| 表头普通、数据行等结构、需保留/截断行数 | `fill` | 逐行填 + 截断多余行 + 可选合计行 |
| 表头含**纵向合并(vMerge)**且需干净重填 | `rebuild` | 重建表避免合并锚点撞车 |
| 仅**末列**合并（如考核组成） | `fill` | 保留模板原生合并，勿误判 rebuild |
| **嵌套多行合并表头**（如学期分配信息表） | `cells` | rebuild 无法重建多行嵌套表头，按坐标精填 |

## 2. vMerge（纵向合并）陷阱

- 症状：表1/表3 出现内容重复行、序号错位。
- 判据：`row.cells[ci]` 在合并区间内返回**同一 cell 对象**；`del rows` 后再按索引填会错位。
- 修正：
  1. 合并表**先按原始索引填值，最后再删多余尾部行**（`del_row_range` 在填值后）。
  2. `rebuild` 仅对模板**实际合并的列**加 `vMerge`，否则保真校验报"引入新行结构"。
  3. 表3 仅前 4 列纵向合并、后 2 列不合并（模板实测）。

## 3. 合计行定位

- 症状：`hr+len` 把真实合计行当数据行覆盖，再报"合计行缺失"。
- 修正：合计行恒为**模板末行** → `trow = tbl.rows[-1]`，填完删 `hr+len .. 末-2`。

## 4. 段落替换

- 模板段落常带**尾随空格** → 精确匹配失败。
- 修正：`cur in pdata` 优先，回退 `cur.rstrip() in pdata`。
- 多 run 段落：合并 runs 文本做子串/整段替换，保留首 run 样式。

## 5. 单元格填值

- 症状：合并参考书列（多段落）第二段旧文本残留。
- 修正：`setc` 填值前 `remove` 多余段落，只留首段。

## 6. 校验参数固化（D）

- `verify_faith.py` 支持 `--spec <spec.json>`，从 spec 的 `verify` 段读取
  `forbidden`（旧文本）与 `expect`（关键字段），无需手敲长串参数。
- 内容级断言自动扫描含「配分/比例」列的表，合计应=100。

## 7. 单一真源（A/C）

- 身份字段 + 共享骨架（模块/周次/考核/评价）全部进 `course.yaml`。
- `build_course.py` 读 yaml → 叠加到各 `*-data.json` → 一键渲染三件套并校验。
- 改 yaml 一处（教师/代码/学校）即三文档同步。
